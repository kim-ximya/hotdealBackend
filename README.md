# Selenium 핫딜 수집 서버

Selenium이 실행한 **헤드리스 Chrome**에서 아카라이브 핫딜 목록을 **기본 3분(180초)마다** 수집합니다. Chrome 창을 표시하지 않고 백그라운드에서 실행하며, 게시글을 ID로 병합해 JSON 파일에 저장하고 웹페이지·Windows 앱 등에서 사용할 수 있는 조회 API를 제공합니다.

```text
헤드리스 Chrome → 핫딜 목록 HTML → 게시글 파싱 → articles.json 저장 → 조회 API
                    ↑ 설정한 간격마다 실행
```

## 실행

### Windows 1.1 설치판

GitHub [1.1.0 릴리즈](https://github.com/kim-ximya/hotdealBackend/releases/tag/v1.1.0)의 `HotdealCollector-Setup-1.1.0-x64.exe`로 설치합니다. Node.js는 필요 없으며 Google Chrome은 필요합니다. 설치판 데이터는 `%APPDATA%\HotdealCollector`에 보관합니다. 설치·업데이트·빌드 방법은 [1.1 사용 안내](docs/release-1.1.md)를 확인하세요.

타이틀 아래에는 실행 중인 앱 버전을 표시합니다. 설치판은 시작 약 10초 후와 이후 6시간마다 공개 GitHub 정식 릴리즈를 확인합니다. 새 버전이 있을 때만 타이틀 옆 **업데이트 v…** 버튼이 나타나며, 누르면 다운로드 진행률을 표시합니다. 완료 후 **재시작 및 설치**를 누르면 수집 서버·전용 Chrome을 정상 종료하고 설치·재실행합니다. 재실행 후 **서버 시작**으로 수집을 재개하세요. 종료에 실패하면 설치하지 않고 현재 앱을 유지합니다. 일반 앱 종료로는 자동 설치하지 않으며 개발 모드에서는 업데이트를 확인하지 않습니다. 1.0.0 사용자는 1.1.0을 한 번 직접 설치해야 합니다. [electron-updater 공식 동작 안내](https://www.electron.build/v26/docs/features/auto-update/).

### 프로젝트에서 실행

Node.js 22.12 이상과 Chrome이 필요합니다. ChromeDriver는 공식 Selenium Manager가 준비합니다.

```powershell
npm install
npm run desktop
```

Electron으로 만든 **핫딜 수집 관리자** 창이 열립니다. 앱을 열기만 하면 수집을 시작하지 않으며, **서버 시작**을 누르면 Chrome을 백그라운드에서 실행하고 즉시 첫 수집을 시작합니다. 수집용 Chrome 창은 표시되지 않습니다.
설치 후에는 루트의 `start-desktop.cmd`를 더블클릭해 실행할 수도 있습니다.

첫 화면의 **핫딜 목록** 탭에는 저장된 게시글을 최신 ID 순으로 50개씩 표시합니다. 제목·분류·작성자·작성일·조회·추천·댓글 수를 확인할 수 있고, 제목을 누르면 기본 브라우저에서 원문을 엽니다. 저장되지 않은 정보는 `—`로 표시합니다.

가장 최근 수집에서 새로 추가·보관된 글은 제목 앞에 **New** 태그를 표시합니다. 새 글이 들어오면 기존 태그를 지우고 해당 수집의 새 글에만 붙입니다. 새 글이 없는 수집·목록 새로고침·관심 품목 필터·앱 재시작은 태그를 유지하며, 수집이나 저장 실패 시에도 이전 태그를 보존합니다. 빈 데이터의 첫 수집은 수집한 글 모두에 표시합니다. 원본 제목은 바꾸지 않고 JSON의 `isNew` 값으로 관리합니다. 기존 JSON에 이 값이 없으면 태그 없이 읽고, 다음 새 글부터 적용합니다.

서버 중지 상태에서는 저장된 `articles.json`을 읽고, 실행·외부 서버 연결 상태에서는 로컬 API를 조회합니다. 수집 성공 후 목록이 자동 갱신되며 **목록 새로고침**은 저장 데이터만 다시 조회합니다. 목록 열기·새로고침·페이지 이동은 추가 크롤링을 요청하지 않습니다. 목록 읽기에 실패하면 오류를 표시하고 이미 표시한 목록은 유지합니다.

**설정** 탭은 수집·브라우저·알림·시작으로 나누고 기능별 카드를 넓게 배치합니다. **실행 로그 열기**를 누르면 별도 창에서 현재 앱 세션의 최근 500개 로그를 확인합니다. 오류·브라우저 필터, 자동 스크롤, 로그 비우기를 제공하며 창을 닫아도 서버와 로그 보관은 계속됩니다. 다시 열면 현재 로그를 이어서 표시하며, 같은 로그 창이 이미 열려 있으면 그 창을 앞으로 가져옵니다. 트레이로 숨기면 로그 창도 함께 숨깁니다.

서버 제어와 보관 수·최근 수집·다음 수집·브라우저 상태를 작은 상단 패널 하나에 통합해 각 탭에서 공통으로 표시합니다. 상태 값에 마우스를 올리면 상세 날짜·예약 시각·수집 횟수를 확인할 수 있습니다. 목록 필터와 새로고침은 게시글 패널 상단에 함께 표시합니다.

**관심 품목** 탭에서 상품 키워드를 등록·삭제하고 **등록한 관심 품목의 새 글만 알림**을 설정할 수 있습니다. 핫딜 목록의 **관심 품목만 보기**로 일치하는 글을 모아 봅니다. 제목에 키워드 하나라도 포함되면 일치하며 영문 대소문자는 구분하지 않습니다. 등록 내용과 알림 범위는 재시작 후에도 유지됩니다. 자세한 비교 규칙과 저장 위치는 [관심 품목 안내](docs/interests.md)를 참고하세요. 1.1.0부터 설치판에 포함됩니다.

| UI 기능 | 동작 |
| --- | --- |
| 서버 시작·중지 | 수집 예약과 로컬 API를 시작·종료합니다. 중지 시 전용 Chrome도 종료합니다. |
| 수집 간격 | 분·초 단위로 입력하고 **간격 적용**을 누릅니다. 중지 상태에서도 저장되며 재시작 후 유지됩니다. |
| User-Agent | **브라우저** 탭에서 입력하고 **User-Agent 저장**을 누릅니다. 다음 서버 시작부터 적용되며, 빈 값은 Chrome 기본값을 사용합니다. |
| 지금 수집 | 다음 예약을 기다리지 않고 수집합니다. 이미 수집 중이면 중복 실행하지 않습니다. |
| 상태 | 보관 수, 마지막 성공 시각, 다음 수집까지의 시간, 브라우저 상태, 이번 실행의 성공·시도 횟수를 표시합니다. |
| 실행 로그 열기 | 별도 창에서 현재 앱 세션의 최근 500개 로그, 오류·브라우저 필터, 자동 스크롤을 제공합니다. 로그 비우기는 세션 로그만 지우며 저장된 게시글은 유지합니다. |
| 저장 폴더 열기 | JSON·설정이 있는 폴더를 탐색기로 엽니다. |

**트레이로 숨기기**, 창의 **최소화(—)** 또는 **닫기(X)**를 누르면 창만 숨깁니다. 앱에서 시작한 서버·수집 예약·로컬 API·헤드리스 Chrome은 계속 실행됩니다. Windows 작업 표시줄의 트레이 아이콘(민트색 H)을 클릭하거나 우클릭 → **창 열기**로 복원합니다. 아이콘이 보이지 않으면 작업 표시줄의 숨겨진 아이콘(∧)을 확인하세요. `start-desktop.cmd`를 다시 실행해도 기존 창을 복원하며 앱·서버를 중복 실행하지 않습니다.

완전히 종료하려면 트레이 아이콘을 우클릭해 **앱 완전 종료**를 선택하세요. 앱에서 실행한 서버와 전용 Chrome을 정상 종료한 뒤 트레이 아이콘도 제거합니다. 종료 실패 시 창을 다시 열어 오류를 표시하며 앱을 유지합니다. 별도로 실행 중인 호환 서버가 같은 포트에 있으면 HTTP API로 연결하며, 이 경우 **연결 해제**와 앱 종료는 외부 서버를 종료하지 않습니다. 외부 서버의 과거 콘솔 로그는 가져오지 않고, 연결 이후의 수집 결과·오류를 상태 API로 확인해 표시합니다.

UI와 수집 서버는 별도 프로세스로 실행합니다. 수집은 기존 Selenium 코드와 JSON API를 공유합니다. 화면에는 Node.js 접근을 허용하지 않으며, [Electron의 context isolation·IPC 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)을 따라 제한된 제어 기능만 전달합니다.

### Windows 로그인 시 자동 실행

**설정 → 시작**에서 **Windows 로그인 시 자동 실행**을 선택하고 **자동 실행 설정 적용**을 누릅니다. 현재 Windows 사용자에게만 등록하며 관리자 권한은 필요하지 않습니다. 로그인하면 앱 창을 표시하지 않고 트레이에 머물며, 저장된 수집 간격·User-Agent로 수집 서버를 자동 시작합니다. 자동 시작에 실패하면 창을 열어 상태와 로그를 확인할 수 있게 합니다.

체크를 해제하고 적용하면 다음 로그인부터 자동 실행하지 않습니다. 현재 실행 중인 서버는 계속 동작합니다. 작업 관리자나 Windows 시작 앱 설정에서 사용 안 함으로 바꾼 경우 **상태 새로고침**으로 확인할 수 있습니다. 자동 실행 기능은 [Electron의 로그인 항목 API](https://www.electronjs.org/docs/latest/api/app#appsetloginitemsettingssettings-macos-windows)를 사용합니다.

현재는 프로젝트에서 실행하는 앱이므로 프로젝트 폴더와 설치된 Electron을 같은 위치에 유지하세요. 프로젝트를 옮긴 경우 새 위치에서 자동 실행 설정을 다시 적용합니다. `start-desktop.cmd`로 직접 열면 기존처럼 창을 표시하며 수집은 **서버 시작**으로 제어합니다. 자동 실행 등록은 Windows 로그인 이후에 동작합니다.

### 새 게시글 알림

새 글을 **수집하고 JSON 저장에 성공하면**, 화면 오른쪽 아래에 Electron 플로팅 알림과 작은 알림음을 표시합니다. 메인 창을 트레이로 숨긴 상태에서도 동작하며, 알림이 나타날 때 작업 중인 창의 키보드 포커스를 가져오지 않습니다. 알림 위치는 관리자 창이 놓인 모니터의 작업 영역을 기준으로 하므로 작업 표시줄을 가리지 않습니다.

- 여러 새 글은 한 알림으로 묶어 최신 3개의 제목·분류·작성자를 보여 줍니다. 나머지 개수도 표시합니다.
- 제목을 누르면 기본 브라우저에서 원문을 열고, **목록 열기**는 관리자 창의 핫딜 목록을 엽니다.
- 기본 8초 후 닫히며, 마우스를 올리면 유지하고 벗어나면 다시 8초 후 닫힙니다. 닫기(×) 또는 Escape로도 닫습니다.
- 카드를 오른쪽으로 드래그한 뒤 놓으면 닫힙니다. 카드 폭의 약 1/4(최대 96px)을 밀거나, 12px 이상 민 상태로 마우스가 해당 모니터의 오른쪽 가장자리에 도달하면 닫습니다. 짧게 움직이거나 드래그를 취소하면 원래 위치로 돌아옵니다. 드래그 중에는 자동으로 닫히지 않으며, 제목을 드래그해도 원문이 열리지 않습니다. 닫기·목록 열기 버튼은 클릭용으로 유지합니다.
- 마우스를 놓은 위치부터 닫기·복귀 애니메이션을 이어갑니다. 닫기 조건을 충족하면 약 0.26초 동안 오른쪽으로 밀려나며 투명해지고, 충족하지 않으면 약 0.3초 동안 기본 위치로 부드럽게 돌아옵니다. 전환 중에도 자동 닫기를 멈추며, 닫기 전환 도중 새 알림이 오면 전환 완료 후 새 창으로 표시합니다.
- 처음 데이터가 없는 상태의 첫 수집은 기준 목록으로 삼아 알리지 않습니다. 이후에는 이전에 확인한 최대 게시글 ID보다 큰 일반 글만 알립니다. 기존 글 수정·댓글/조회수 변경·보관 한도로 삭제되었다가 다시 보인 오래된 글에는 알리지 않습니다.
- 이미 저장된 데이터가 있다면 서버 시작 시 그 목록을 기준으로 새 글을 판단합니다. 중지 중 올라온 글도 재시작 후 첫 페이지에서 수집되면 알릴 수 있습니다. 수집·저장 실패와 공지는 알리지 않습니다.

**설정 → 알림**에서 플로팅 알림과 소리를 각각 설정한 후 **알림 설정 저장**을 누르면 즉시 적용되며 재시작 후에도 유지됩니다. 기본값은 모두 켜짐이고, 설정 파일은 `.local/desktop/notification-settings.json`입니다. 소리 크기는 Windows의 앱별 볼륨 설정에도 영향을 받습니다.

**테스트 알림 표시**는 서버를 시작하지 않아도 사용할 수 있고, 실제 게시글을 수집하거나 JSON에 테스트 글을 추가하지 않습니다. 알림을 꺼도 미리보기는 표시하며, 소리는 저장된 설정을 따릅니다. 알림 기능은 데스크톱 앱이 실행 중일 때 동작합니다. 터미널 서버만 실행하는 경우에는 UI 알림을 표시하지 않습니다. 외부 서버 연결 시에는 연결 당시 목록을 기준으로 해당 서버 API의 최신 1000개를 확인해 새 글을 감지합니다.

이는 설정한 수집 간격으로 확인한 결과를 알리는 기능입니다. 수집 사이에 첫 페이지 밖으로 밀려난 글을 모두 복구하거나 게시 즉시 알리는 기능은 아닙니다.

**UI로 실행한 서버는 저장된 `settings.json`의 간격을 우선 사용하며 `CRAWL_INTERVAL_SECONDS`는 사용하지 않습니다.** 나머지 `.env` 설정은 그대로 적용됩니다. 기존 `.local/selenium-server` 데이터도 이어서 사용합니다. 같은 데이터 폴더로 서버 두 개를 별도 포트에서 동시에 실행하지 마세요.

User-Agent는 데이터 폴더의 `browser-settings.json`에 별도로 저장합니다. 실행 중 저장하면 **재시작 필요** 안내가 표시되며, 서버를 중지하고 다시 시작하면 적용됩니다. 입력은 개행 없는 영문·숫자·기호(ASCII) 1024자 이하이며, 앞뒤 공백은 제거합니다. 외부 서버에 연결된 상태에서는 이 설정을 편집할 수 없습니다. UI는 저장한 User-Agent를 사용하고 `.env`의 `SELENIUM_USER_AGENT`는 사용하지 않습니다.

pnpm을 사용한다면 다음과 같이 실행합니다. Electron 설치 스크립트가 차단되는 환경에서는 `desktop:install`로 실행 파일을 준비합니다.

```powershell
pnpm install
pnpm desktop:install
pnpm desktop
```

최초 의존성·Electron·ChromeDriver 준비에는 다운로드가 필요합니다. Windows 설치 패키지는 `pnpm dist:win`으로 만들 수 있습니다.

### 터미널에서 서버만 실행

```powershell
npm start
```

pnpm을 사용하면 `pnpm install` 후 `pnpm start`로 실행할 수 있습니다. 시작 시 즉시 한 번 수집하며, 이후 설정한 간격으로 수집합니다. 서버 실행 중 헤드리스 Chrome 프로세스를 유지합니다. 종료는 `Ctrl+C`이며, 수집 예약과 백그라운드 브라우저를 함께 종료합니다.

터미널에서 시작할 때 같은 포트의 서버가 이미 실행 중이면 먼저 종료하세요.

- [게시글 목록](http://127.0.0.1:38471/api/articles)
- [수집 상태](http://127.0.0.1:38471/api/status)
- [현재 수집 간격](http://127.0.0.1:38471/api/settings)

## 수집 간격 및 설정

설정하지 않으면 간격은 180초입니다. 실행 시 지정하려면 다음처럼 환경변수를 사용합니다.

```powershell
$env:CRAWL_INTERVAL_SECONDS = '300'
node main.js
```

서버 실행 중에는 API로 변경할 수 있습니다. 값은 **초 단위의 정수(1~86400)**입니다.

```powershell
Invoke-RestMethod -Method Put `
  -Uri 'http://127.0.0.1:38471/api/settings' `
  -ContentType 'application/json' `
  -Body '{"intervalSeconds":180}'
```

변경한 간격은 `settings.json`에 저장되어 재시작 후에도 유지됩니다. 우선순위는 **환경변수/`.env`의 명시적 값 → 저장된 설정 → 기본 180초**입니다. 환경변수로 간격을 고정하면 실행 중 API 변경은 적용되지만, 다음 재시작 시 환경변수가 다시 우선합니다.

루트의 `.env.example`을 `.env`로 복사해 설정할 수도 있습니다. 서버가 `.env`를 자동으로 읽으며, 이미 지정된 외부 환경변수를 우선합니다.

| 설정 | 기본값 | 용도 |
| --- | --- | --- |
| `CRAWL_INTERVAL_SECONDS` | 180 또는 저장된 설정 | 수집 간격(초) |
| `PORT` | 38471 | API 포트 |
| `DATA_DIR` | `.local/selenium-server` | 게시글·설정·브라우저 프로필·드라이버 저장 폴더 |
| `MAX_ARTICLES` | 10000 | 최신 ID부터 보관할 최대 게시글 수(1~100000) |
| `SELENIUM_WAIT_SECONDS` | 120 | 접속·보안 확인 후 목록을 기다리는 시간(초) |
| `SELENIUM_CHROME_BINARY` | 자동 탐색 | Chrome 실행 파일 경로 |
| `SELENIUM_USER_AGENT` | 저장값 또는 Chrome 기본값 | 터미널 실행 시 User-Agent 재정의. 빈 값은 Chrome 기본값. UI는 저장값 사용 |
| `FRONTEND_ORIGINS` | 없음 | CORS를 허용할 정확한 HTTP(S) 출처 목록(쉼표 구분) |

한 번의 수집이 오래 걸리면 중간에 예정된 실행은 건너뜁니다. 작업을 겹쳐 실행하거나 놓친 횟수만큼 연속 요청하지 않습니다. 간격 변경은 예약을 다시 계산하며, 진행 중인 수집은 그대로 완료합니다.

터미널 서버의 User-Agent 우선순위는 **명시적 `SELENIUM_USER_AGENT` → `browser-settings.json` → Chrome 기본값**입니다. UA 변경은 Chrome의 `--user-agent` 옵션에 적용하며, `/api/status`의 `browser.userAgent`는 해당 서버 실행에서 지정한 값(빈 문자열이면 Chrome 기본값)을 표시합니다. User-Agent 변경이 사이트의 보안 확인을 해결한다는 보장은 없습니다.

## 저장 방식

기본 파일은 `.local/selenium-server/articles.json`입니다. 임시 파일에 작성·동기화한 후 교체하며, 파일 저장 성공 후에만 API의 조회 데이터를 갱신합니다. 수집이나 저장 실패 시 마지막 성공 데이터를 유지합니다. 서버 재시작 시 기존 JSON을 읽고 누적 수집을 이어갑니다. 파일이 손상되었으면 이를 덮어쓰지 않고 시작 오류를 출력합니다.

- 새로운 게시글 ID는 추가하고, 이미 있는 ID는 조회·댓글 수 등 현재 정보를 갱신합니다.
- `firstSeenAt`은 처음 수집한 시각, `lastSeenAt`은 마지막으로 수집한 시각입니다.
- 이전에 수집한 글이 첫 페이지에서 밀려나도 보관합니다. 보관 한도를 넘으면 가장 오래된 ID부터 제거합니다.
- 작성자 이름이 `*`로 시작하는 글은 제외합니다. 기타 공지 여부는 `isNotice`에 표시합니다.
- HTML의 분류 링크와 게시글 링크를 구분하며, 선택 정보가 없으면 `null`을 사용합니다.
- **현재 수집 범위는 첫 페이지입니다.** 수집 간격 사이에 첫 페이지 밖으로 밀려난 글, 수집 중단 동안의 모든 글을 복구하지는 않습니다. 과거 글 전체 수집이나 삭제·종료된 딜의 추적 기능은 포함하지 않습니다.

저장 파일 예시:

```json
{
  "schemaVersion": 1,
  "channel": "/b/hotdeal",
  "sourceUrl": "https://arca.live/b/hotdeal",
  "updatedAt": "2026-10-13T04:00:00.000Z",
  "latestCount": 26,
  "total": 100,
  "articles": [
    {
      "id": "185704738",
      "url": "https://arca.live/b/hotdeal/185704738",
      "title": "하우스 플리퍼 2",
      "category": "SW/게임",
      "author": "작성자",
      "createdAt": "2026-10-12T08:24:14.000Z",
      "views": 23,
      "recommendations": 0,
      "commentCount": null,
      "isNotice": false,
      "firstSeenAt": "2026-10-13T03:00:00.000Z",
      "lastSeenAt": "2026-10-13T04:00:00.000Z"
    }
  ]
}
```

위 JSON은 형식을 보여 주는 예시이며, `articles`는 한 건만 발췌했습니다.

## API

| 메서드·경로 | 내용 |
| --- | --- |
| `GET /api/articles?limit=100&offset=0` | 저장된 목록. 기본 100개, 최대 1000개, 최신 ID 순 |
| `GET /api/status` | 실행 상태, 다음 수집 시각, 성공 횟수, 최근 오류, 브라우저 상태 |
| `GET /api/settings` | 현재 `intervalSeconds` |
| `PUT /api/settings` | JSON `{"intervalSeconds":180}`으로 간격 변경·저장 |
| `POST /api/collect` | JSON `{}`로 즉시 수집. 진행 중이면 같은 작업에 합류 |

조회 API에는 저장 형식에 `limit`, `offset`, `returnedCount`가 추가됩니다. `total`은 전체 보관 수, `latestCount`는 마지막 수집 목록의 개수입니다. 조회 API 호출은 사이트에 추가 접속하지 않습니다.

즉시 수집 요청은 `202 Accepted`를 반환합니다. 완료 여부는 상태 API로 확인합니다.

```powershell
Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:38471/api/collect' `
  -ContentType 'application/json' `
  -Body '{}'
```

상태의 주요 항목은 `isCollecting`, `nextRunAt`, `lastSuccessAt`, `lastError`, `attempts`, `successes`, `consecutiveFailures`, `articleCount`입니다. `lastSuccessAt`은 재시작 시 저장 파일의 갱신 시각으로 복구하고, 실행 횟수는 이번 서버 실행 기준입니다. `browser.headless`는 `true`이며, `browser.effectiveUserAgent`는 Chrome에서 확인한 실제 User-Agent입니다. `browser.userAgent`는 설정한 재정의 값입니다.

`browser.attentionRequired`가 `true`이면 사이트 보안 확인이 감지된 상태입니다. 헤드리스 모드에서는 사용자가 화면에서 직접 확인할 수 없습니다. 지정한 대기 시간 내 목록을 얻지 못하면 `lastError`와 UI 로그에 실패를 표시하고 마지막 정상 JSON을 유지하며 다음 예약 시 다시 시도합니다. 보안 확인 화면은 게시글 목록으로 저장하지 않습니다. 저장된 User-Agent, 네트워크와 사이트 접속 상태를 확인하세요. 창 표시 모드로 자동 전환하거나 보안 확인을 자동으로 해결하지 않습니다.

서버는 `127.0.0.1`에 바인딩합니다. Windows 앱의 일반 HTTP 클라이언트에서는 바로 사용할 수 있습니다. 다른 포트에서 실행하는 웹 프론트엔드는 `.env`에 출처를 등록합니다.

```dotenv
FRONTEND_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

설정 변경 API도 해당 출처에서 사용할 수 있습니다. 등록되지 않은 출처와 다른 Host의 요청은 거부합니다. `file://` 페이지 대신 로컬 개발 서버를 사용하세요.

## 검증

```powershell
node --test
```

로컬 테스트는 HTML 파싱·필터링, 수집 예약, 작업 중복 방지, 간격 변경 저장, 게시글 병합·보관 한도, 파일 재로딩, 실패 시 기존 데이터 유지, API와 CORS를 검증합니다. Electron 제어기의 시작·중지·재시작, 즉시 수집, 외부 서버 연결 해제, 로그 한도, 시작 중 종료도 검증합니다. 알림 테스트는 첫 수집 제외, ID 중복 방지, 저장 실패 시 알림 억제, 설정 보존, 묶음 표시, 자동 닫기·마우스 유지, IPC 접근 제한을 검증하며 실제 Chrome·사이트 접속을 사용하지 않습니다. 실제 사이트 수집 여부는 앱의 상태·로그 또는 `/api/status`와 `/api/articles`에서 확인합니다. 브라우저 보안 확인을 자동으로 통과시키거나 자동화 탐지를 숨기는 설정은 없습니다.
