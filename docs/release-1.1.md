# 핫딜 수집 관리자 1.1.0

Windows x64용 개인용 핫딜 수집 앱입니다. 아카라이브 공식 앱이 아닙니다.

## 설치 및 기존 버전 업데이트

1. Google Chrome이 설치되어 있는지 확인하세요. Node.js는 별도로 설치하지 않아도 됩니다.
2. 기존 앱이 실행 중이면 트레이 메뉴에서 **앱 완전 종료**를 선택합니다.
3. `HotdealCollector-Setup-1.1.0-x64.exe`를 실행합니다. 기존 설치 폴더를 사용하면 앱과 데이터를 이어서 사용할 수 있습니다.
4. 앱에서 **서버 시작**을 누릅니다. 기본 3분 간격으로 Chrome 창 없이 핫딜 목록을 수집합니다.

**1.0.0에는 업데이트 기능이 없어 1.1.0은 한 번 직접 설치해야 합니다.** 1.1.0부터 이후 버전을 앱 안에서 업데이트합니다.

## 1.1의 새 기능

- **관심 품목**: 상품 키워드 등록·삭제, 관심 품목만 목록 보기, 관심 품목의 새 글만 알림.
- **New 태그**: 가장 최근 새 글이 추가된 수집에서 발견한 게시글을 표시. 새 글이 없으면 기존 표시 유지.
- **넓어진 목록과 설정**: 서버 제어·상태를 작은 패널에 통합하고 목록 영역을 확장. 설정은 기능별 카드와 탭으로 구성.
- **별도 실행 로그 창**: 설정의 **실행 로그 열기**에서 실시간 로그·필터·자동 스크롤·세션 로그 비우기.
- **앱 버전 및 업데이트**: 타이틀 아래 현재 버전 표시. 새 버전이 있을 때만 타이틀 옆 업데이트 버튼 표시.

## 자동 업데이트 사용

설치판은 시작 약 10초 후와 이후 6시간마다 이 프로젝트의 공개 GitHub 정식 릴리즈를 확인합니다. 최신 버전이거나 개발 모드이면 업데이트 버튼은 숨겨집니다. 인터넷 연결이 없어도 수집 기능은 계속 사용할 수 있고 확인 실패는 로그와 안내에 표시합니다.

1. 타이틀 옆 **업데이트 v…**를 눌러 다운로드합니다. 진행률이 버튼에 표시됩니다. 다운로드 중 수집 서버는 계속 동작합니다.
2. 다운로드 후 **재시작 및 설치**를 누릅니다. 수집 서버와 전용 Chrome을 정상 종료한 뒤 설치하고 앱을 다시 실행합니다. 재실행 후 **서버 시작**으로 수집을 재개하세요.

일반 종료만으로 업데이트를 강제로 설치하지 않습니다. 다운로드·파일 검증·서버 종료에 실패하면 현재 앱을 유지하고 다시 시도할 수 있습니다. 다운로드 파일은 electron-updater가 릴리즈 메타데이터의 SHA-512로 검증합니다. 현재 설치 파일에는 Authenticode 코드 서명이 없어 Windows에서 게시자 확인 안내가 나올 수 있습니다.

## 데이터와 실행

설치판 데이터는 `%APPDATA%\HotdealCollector`에 저장합니다. 업데이트·제거 시 자동 삭제하지 않습니다.

- `collector\articles.json`: 수집 게시글과 New 표시
- `collector\settings.json`, `collector\browser-settings.json`: 수집 간격·User-Agent
- `collector\profile`, `collector\driver-cache`: 수집 브라우저 프로필·드라이버
- `notification-settings.json`, `interest-settings.json`: 알림·관심 품목 설정

**설정 → 수집 → 저장 폴더 열기**에서 실제 저장 위치를 확인하세요. 프로젝트의 `.local` 데이터·`.env`·쿠키·인증정보는 설치 파일에 포함하지 않습니다. 기존 개발판에서 데이터를 옮기는 방법은 [1.0 사용 안내](https://github.com/kim-ximya/hotdealBackend/blob/main/docs/release-1.0.md)를 참고하세요.

창을 닫거나 최소화하면 트레이로 숨겨지고 수집은 계속됩니다. 완전히 종료하려면 트레이 아이콘을 우클릭해 **앱 완전 종료**를 선택하세요. Windows 로그인 자동 실행은 **설정 → 시작**에서 등록합니다. 업데이트로 설치 경로가 바뀌면 새 경로에서 다시 등록하세요.

`http://127.0.0.1:38471`의 로컬 JSON API를 다른 프론트엔드에서 사용할 수 있습니다. 개발판과 설치판의 기본 포트가 같으므로 동시에 서버를 실행하지 마세요. 고급 실행 환경변수 `HOTDEAL_USER_DATA_DIR`, `DATA_DIR`, `PORT`도 지원합니다.

수집 범위는 채널 첫 페이지입니다. 수집 사이 첫 페이지 밖으로 밀려난 글은 누락될 수 있고 사이트 구조·접속 확인 정책에 따라 실패할 수 있습니다. 실패 시 마지막 정상 JSON을 유지합니다.

## 개발 및 다음 릴리즈

```powershell
pnpm install --frozen-lockfile
pnpm desktop:install
pnpm test
pnpm dist:win
```

`release`에 설치 `.exe`, `.exe.blockmap`, `latest.yml`, `SHA256SUMS.txt`, 사용 안내가 생성됩니다. `--publish never`로 빌드하며 자동 업로드하지 않습니다. 이후 버전은 package.json의 버전을 높이고 동일 공개 저장소의 정식 GitHub Release에 새 설치 파일·blockmap·latest.yml을 모두 첨부해야 합니다. 메타데이터와 설치 파일이 같은 버전인지 확인한 뒤 릴리즈를 게시하세요. `.env`, `.local`, 개인 인증정보는 배포하지 않습니다.

자동 업데이트 구현: [electron-builder v26 공식 안내](https://www.electron.build/v26/docs/features/auto-update/).
