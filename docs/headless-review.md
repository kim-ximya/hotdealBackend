## 결론

현재 Selenium 수집기를 Chrome 헤드리스 모드로 실행하는 것은 가능합니다. 다만 이번 실제 사이트 검증에서는 Cloudflare 보안 확인 응답을 받아 게시글을 수집하지 못했습니다. 따라서 실행 옵션만 바꾸면 안정적으로 무인 수집된다고 결론 내릴 수 없습니다.

운영 서버, UI, 기존 게시글 JSON, 설정과 브라우저 프로필은 변경하지 않았습니다.

## 기술적으로 필요한 변경

`src/selenium-collector.js`에서 Chrome 옵션에 다음 인자를 추가하면 표시되는 Chrome 창 없이 실행할 수 있습니다.

```js
options.addArguments('--headless=new');
```

Chrome 프로세스 자체는 계속 실행됩니다. JavaScript 실행, HTML 획득과 기존 파서는 그대로 사용할 수 있으므로 수집 예약, JSON 저장, 조회 API를 다시 설계할 필요는 없습니다. Chrome은 공식적으로 헤드리스 실행을 지원하고 Selenium에서 실행 옵션을 전달하는 방법도 안내합니다.

참고: [Chrome Headless 공식 문서](https://developer.chrome.com/docs/automation-and-testing/headless), [Selenium Chrome 옵션 문서](https://www.selenium.dev/documentation/webdriver/browsers/chrome/).

## 권장 구현 방향

1. **헤드리스/창 표시 모드를 선택 가능하게 추가**합니다. 선택값은 저장하고 다음 서버 시작에 적용합니다. 이미 실행 중인 Chrome의 실행 옵션을 바꾸려면 브라우저를 다시 시작해야 합니다.
2. 헤드리스에서 보안 확인이 나타나면 **수집 실패와 사용자 확인 필요 상태를 UI에 표시**하고 마지막 저장 데이터를 유지합니다. 현재의 ‘열린 Chrome에서 확인하세요’ 안내도 모드에 맞게 변경합니다.
3. 필요하면 사용자가 창 표시 모드로 전환해 직접 접속 상태를 확인하도록 합니다. 창 표시 모드에서 확인을 마친 프로필을 이후 헤드리스에서 재사용하더라도 계속 성공한다는 보장은 없습니다.
4. 헤드리스에서 정상 목록을 얻은 환경에서 기본 3분 주기의 반복 수집·브라우저 재시작까지 검증한 후 기본 모드 전환을 결정합니다.

Chrome 창을 한 번도 띄우지 않는 것이 필수 조건이라면, 현재 테스트 결과로는 그 조건을 충족하는 안정적인 수집 방식이 확보되지 않았습니다. 사용자가 직접 보안 확인을 완료할 수 있는 창 표시 모드를 복구 수단으로 남기는 것이 현실적인 설계입니다.
